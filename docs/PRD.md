# 体重与饮食记录网站 PRD v1.0

## 1. 项目目标

创建一个个人使用的体重、饮食、排便和生理期记录网站。用户可以用自然语言输入一大段描述，系统自动提取当天数据、估算热量、分析饮食结构，并长期保存。

本项目最重要的要求：

- 保留现有历史数据。
- 历史数据只追加，不覆盖。
- 支持按日期查询。
- 支持体重趋势、7日平均体重、热量趋势。
- 分析时必须结合排便和生理期。
- 官方热量、包装营养表、用户明确提供的热量优先。
- 对不确定数据使用区间和置信状态，不伪造精确值。

## 2. 用户基本资料

- 性别：女性
- 年龄：30岁
- 身高：160cm
- 骨架：中小骨架
- 近期体重：约48.75–50.2kg
- 基础代谢估算：约1175–1185 kcal/天
- 日常维持热量初始估算：约1500–1650 kcal/天
- 轻微减脂参考区间：约1300–1450 kcal/天
- 分析必须考虑生理期、未排便、高盐、高碳水、大量水果造成的短期体重波动。

以上区间仅作为应用初始规则，应允许在设置页修改。

## 3. 页面设计

### 3.1 今日记录页

包含：

- 日期，默认今天。
- 晨起体重。
- 是否排便。
- 生理期状态：未到、还有N天、第N天、已结束。
- 自然语言输入框。
- 图片上传，可上传食品包装、菜单、营养表、餐食照片。
- AI解析结果预览。
- 早餐、午餐、晚餐、加餐、饮料结构化列表。
- 每项食物数量、热量、热量来源、可信状态。
- 当日总热量区间。
- 当日分析与建议。
- 保存按钮。

保存前必须让用户确认解析结果。保存后默认只追加。

### 3.2 历史日历页

- 月历形式显示每天体重、热量、排便、生理期。
- 点击日期查看完整饮食。
- 支持按日期、食物名称、品牌、餐次搜索。
- 支持显示原始自然语言输入。
- 历史数据默认锁定，修改需要进入“更正模式”。

### 3.3 趋势页

至少包含：

- 每日体重折线。
- 7日滚动平均体重。
- 每日热量区间。
- 排便标记。
- 生理期区间阴影。
- 月平均体重。
- 最低、最高、最近稳定区间。
- 连续多日趋势，而不是用单日体重判断增脂。

### 3.4 查询页

支持自然语言查询，例如：

- 6月22日我吃了什么？
- 最近7天平均体重是多少？
- 哪几天吃了汉堡？
- 哪些天热量超过1600 kcal？
- 月经前7天体重平均比月经后高多少？
- 未排便的第二天体重平均高多少？
- 我最常吃的水果是什么？

V1可以先用结构化筛选实现，AI问答作为V2。

### 3.5 设置页

- 身高、年龄、性别、骨架。
- 目标体重。
- BMR和TDEE参考参数。
- 热量目标。
- 水果重量默认规则。
- 历史记录锁定策略。
- 导入、导出、备份。

## 4. 业务规则

### 4.1 热量优先级

1. 官方营养数据。
2. 食品包装营养表。
3. 用户明确提供的数值。
4. 已保存的品牌食品库。
5. AI估算。

前3类可显示为“较可靠”，AI估算必须显示区间。

### 4.2 体重判断

不得因单日增加0.2–0.5kg直接判断长胖。分析顺序：

1. 称重条件是否一致。
2. 前一天是否排便。
3. 生理期阶段。
4. 前一天是否高盐、高碳水。
5. 前一天是否晚吃或大量吃水果。
6. 查看7日平均和连续趋势。
7. 只有连续1–2周平均体重明显上升，才提示可能存在持续热量盈余。

### 4.3 历史数据保护

- 导入历史记录后，`is_locked=1`。
- 普通编辑不能覆盖锁定记录。
- 用户进入更正模式后，可以新增一个修订版本。
- 每次修改写入审计日志。
- 导出时保留原始版本和最新版本。
- 数据库迁移必须先自动备份。

## 5. 技术方案

推荐：

- 前端：Vue 3 + Vite + TypeScript + Element Plus。
- 图表：ECharts。
- 后端：Python FastAPI。
- 数据库：SQLite，个人使用足够。
- ORM：SQLModel或SQLAlchemy。
- 本地开发：前后端分离。
- 部署：可先本地使用，后续部署到Render、Railway或轻量云服务器。
- AI能力：V1先预留接口；V2再接OpenAI API或其他支持图片理解的模型。

## 6. API建议

- `POST /api/records/parse`：解析自然语言和图片，返回预览，不保存。
- `POST /api/records`：确认后保存。
- `GET /api/records?start=&end=`：查询记录。
- `GET /api/records/{date}`：查询某天。
- `POST /api/records/{date}/revisions`：新增修订，不直接覆盖。
- `GET /api/stats/weight-trend`：体重与7日均值。
- `GET /api/stats/calories`：热量趋势。
- `GET /api/stats/cycle`：生理期相关统计。
- `POST /api/import/history`：导入历史CSV/JSON。
- `GET /api/export`：导出全部数据。

## 7. 验收标准

- 可以完整导入本包中的历史数据。
- 导入后日期、体重、排便、生理期、饮食、热量区间、备注不丢失。
- 重复导入不会生成重复日期。
- 历史记录默认锁定。
- 可以查询任意已记录日期。
- 可以看到7日平均体重。
- 所有估算热量有“估算”标识。
- 用户提供官方热量后，可以新增修订并保留旧值。
- 数据可导出为CSV和JSON。
