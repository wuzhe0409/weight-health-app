# 给 Codex 的主提示词

你现在需要创建一个个人体重与饮食记录网站。请先完整阅读同目录文件：

- `PRD.md`
- `data_dictionary.md`
- `schema.sql`
- `historical_records.json`
- `historical_records.csv`

## 强制要求

1. 不得删除、覆盖或改写历史数据。
2. 历史导入必须幂等：重复导入不会重复插入。
3. 历史数据导入后设置为锁定。
4. 所有不确定热量保留最小值和最大值。
5. 数据状态必须展示：confirmed、mostly_confirmed、estimated、partially_confirmed、incomplete。
6. 生理期与排便必须进入体重趋势分析。
7. 页面必须明确显示7日平均体重，不能只显示单日变化。
8. 先完成可运行的V1，不要一开始接入付费AI API。
9. 技术栈使用 Vue 3 + Vite + TypeScript + Element Plus + ECharts；后端使用 FastAPI + SQLite。
10. 提供一键启动方式，并写清README。

## 实施顺序

### 第1阶段：初始化

- 创建 `frontend` 和 `backend`。
- 后端创建数据库模型、迁移或初始化脚本。
- 前端完成基础布局。
- 提供根目录启动脚本或Makefile。

### 第2阶段：历史数据导入

- 实现JSON和CSV导入。
- 按日期幂等导入。
- 导入后显示记录数量、跳过数量、错误数量。
- 添加审计日志。
- 用本包历史数据进行验证。

### 第3阶段：页面

完成：

1. 今日记录页。
2. 历史日历页。
3. 趋势页。
4. 单日详情页。
5. 设置与导入导出页。

### 第4阶段：统计

- 每日体重图。
- 7日滚动平均。
- 热量区间图。
- 排便标记。
- 生理期标记。
- 最低/最高/最近稳定体重。
- 按食物关键词搜索。

### 第5阶段：自然语言录入占位

先实现一个本地规则解析器：

- 识别日期。
- 识别体重。
- 识别“没拉粑粑/拉了粑粑”。
- 识别“月经第N天/还有N天来”。
- 按早餐、午餐、晚餐、下午、加餐分段。
- 解析结果必须让用户确认后保存。

AI接口先抽象成Provider，不需要真实调用。

## 输出要求

每完成一个阶段：

- 说明完成内容。
- 列出新增文件。
- 给出启动和测试命令。
- 给出数据库验证方法。
- 不要跳过测试。
- 不要擅自改变历史数据。
